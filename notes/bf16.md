## Representation and contract

BF16 has a sign bit, eight exponent bits (bias 127), and seven fraction bits.
For a normal number, x = (-1)^s * (128 + f) * 2^(E - 134).
The smallest positive normal is 2^-126, the smallest positive subnormal is
2^-133, and the largest finite magnitude is (2 - 2^-7) * 2^127. Relative
spacing within a binade is 2^-7; absolute spacing depends on the exponent.
E=255 encodes infinity or NaN. All routines receive integer bit patterns;
no floating-point arithmetic or floating-point instruction is used on RV32I.

The header is the authority. In particular, these routines do not implement
all IEEE floating-point arithmetic behavior: multiply truncates, its NaN
handling is ordered, and square root uses a specified approximation.

## Narrowing binary32

For finite inputs, let H be the retained high half and L the discarded low
half. Round upward when L > 0x8000, or when L == 0x8000 and H is odd. This is
round-to-nearest, ties-to-even. The C form is:

```c
(bits + 0x7FFFu + ((bits >> 16) & 1u)) >> 16
```

An exponent of 255 instead returns the high half unchanged. This preserves
the contract's exact handling of NaN payloads, even when discarding the low
half makes the returned pattern look like infinity. Finite rounding can
carry into the exponent. For ordinary normal results away from overflow,
the relative error is bounded by 2^-8; this is not a global relative bound
for underflow to zero or overflow to infinity.

The assembly directly branches on the discarded half: a nonnegative
`bits << 16` means L < 0x8000. For the other half, shifting again distinguishes
a tie from above-half; a tie adds only H's least significant bit. This avoids
forming the full rounding constant on the common no-increment path. It is
valid for every input, with performance dependent on the input distribution.

## Multiplication

After zero and special-value handling, subnormal significands are shifted
until their leading one reaches bit 7, decreasing their effective exponents
accordingly. Each significand M is then in [128,255]. Form P = Ma * Mb and
E = Ea + Eb - 127. If P >= 2^15, shift P right once and increment E. Dropping
the low seven bits truncates the normalized significand toward zero.

The C product uses the supplied software `__mulsi3`. Assembly specializes
multiplication to the eight-bit multiplier: shift-and-add needs exactly
eight iterations for normalized operands, no function call or stack frame.
Each source subnormal needs at most seven normalization shifts.

Special cases are evaluated in a-then-b order. A NaN first operand is
returned unchanged. An infinite first operand times zero yields 0x7FC0;
otherwise it returns signed infinity, even when b is NaN. Only after that
is b examined. Finite zero products preserve the XOR of the signs.

Underflow also has an important contract quirk: shift the fraction after
removing its hidden bit, rather than shifting the full significand. Thus
`bf16_mul(0x0080, 0x3f00)` is zero, not 0x0040. Exponents below -6 return
signed zero; exponents at least 255 return signed infinity. Tests enforce
these exact results, so replacing them with conventional BF16 behavior
would be incorrect for this assignment.

For products that remain normal, truncation loses less than one output ULP,
so relative error is below 2^-7. This bound does not cover the special
underflow path, infinity, or NaN. The assembly's only shifts by variable
counts on that path have counts in [1,7], avoiding undefined C shifts and
RV32 shift-count masking mistakes.

## Square root

NaNs return unchanged, +infinity returns unchanged, negative nonzero inputs
return 0x7FC0, both zeros return +0, and positive subnormals return +0.
For a positive normal, the unbiased exponent e=E-127 is odd exactly when E
is even. Double M in that case to make e even. The result exponent is
floor((E+127)/2).

The contract asks for the largest integer r satisfying

```
floor(r*r/128) <= M
r*r < 128*(M+1)
r = floor(sqrt(128*(M+1)-1)).
```

Using sqrt(128*M) instead would fail, for example, at M=130. Here the scaled
integer is at most 65535 and r is always in [128,255], so no additional
normalization or exponent saturation is needed for positive normals.

The C version uses eight restoring base-four integer-square-root steps.
It needs only comparison, shifts, addition and subtraction. The assembly
initially expanded these eight steps but remained slower than the best
compiler build. The final version uses a complete 256-byte domain table:
128 fraction fields times two exponent parities. Each byte is generated
from the formula above; table index = 2*f + (E & 1). This covers every
positive normal input, not just published tests or benchmark values.
The special classes are handled before indexing. C and assembly do not
share a table or call each other.

In the O2 ELF, the expanded restoring implementation measured 43.625 net
cycles per call; the table version measured 21.4375. The worst measured
square-root call fell from 79 to 31 instructions. This trades repeated
integer work for 256 bytes of read-only data; no real cache timing benefit
is claimed. The lookup is exact with respect to the assignment's approximate
square-root result.

## Verification and error analysis

All four target builds passed 42 tests each. The host passed 17 tests under
AddressSanitizer and UBSan. Formatting, Cppcheck, whitespace, ISA and external
symbol checks passed. The selected BF16 driver returned 55/55; that is not
the full assignment score.

Narrowing tests cover all 65,536 low halves for 16 retained halves and all
65,536 retained halves for five tie-deciding low halves. Multiply uses
directed cases, a 256-by-256 grid, eight constants over all input patterns,
and arithmetic laws. Square root is checked over all 65,536 patterns with
golden hashes, special-class tests, monotonicity and an error bound.
A further 8,192 random cases cross-check assembly against C.

Host-side binary64 analysis over every positive normal square-root input
measured maximum relative error 0.003883509816495434 (0.38835098165%), first
at 0x0081. It agrees with the contract's stated approximation quality.
Testing every pair of normalized mantissas at exponent 127 measured maximum
multiply relative error 0.007691841802434762 (0.76918418024%), at
0x3f9e times 0x3fd1. This mantissa sweep covers ordinary normal rounding
behavior, not overflow/underflow or special classes. The host-side reference
is Python binary64 multiplication and math.sqrt, separate from target code.
`mytests/bf16_errors.py` reproduces these measurements.

The observed instruction maxima below include the harness measurement
convention. Square root is exhaustive; narrowing and multiply maxima refer
to the tested inputs, not all possible input pairs.

| Function | C maximum | Assembly maximum | Assembly budget |
| --- | ---: | ---: | ---: |
| from_f32 | 15 | 15 | 60 |
| mul | 161 | 142 | 400 |
| sqrt | 108 | 31 | 1500 |

Independent structural bounds also apply: conversion and table lookup have
no loops; multiply has at most 14 total normalization shifts and eight
product iterations. The general paths remain below the required budgets.

## Cycle and size comparison

Measured 2026-11-13 with xPack GCC 15.2.0, binutils 2.45, rv32emu revision
`9dbff65c4d6a40d64d3bbb38f4c5a20d6e885e24`. Flags include
`-march=rv32i_zicsr -mabi=ilp32 -ffreestanding -fno-pic
-fno-stack-protector` and each optimization level below. The emulator is the
system interpreter with ELF loading, without M/A/F/C extensions.

Each table entry is (cycles - measured loop overhead)/16 on identical inputs
and timing regions. Setup and output are excluded. The assembly object is
shared across builds, but caller and overhead code can change the reported
average. Assembly O2 is shown here; speedup uses assembly in the same ELF as
the fastest C build. Counts are deterministic, so no repeated-run median is
needed. rv32emu counts guest instructions; these are not measurements of
pipeline stalls, cache misses, or physical instruction latency.

| Function | C O1 | C O2 | C O3 | C Os | Assembly O2 |
| --- | ---: | ---: | ---: | ---: | ---: |
| from_f32 | 11.0625 | 12.1875 | 13.8125 | 12.1875 | 9.1250 |
| mul | 94.1875 | 87.0625 | 88.5000 | 91.1875 | 67.9375 |
| sqrt | 58.5000 | 55.6875 | 40.3125 | 53.1250 | 21.4375 |

Against the best C builds, assembly speedups are 1.212x for narrowing
(O1: 11.0625/9.125), 1.282x for multiply (O2: 87.0625/67.9375), and 1.762x
for square root (O3: 40.3125/22.875). The O3 compiler expands the restoring
loop, reducing execution work at increased text size. The assembly's table
removes that loop entirely. Conversion benefits from its no-rounding fast
path, while multiply avoids a generic runtime helper and function-call cost.
These benchmark gains are not a claim that every individual call is faster.

## Applications

BF16 is used in machine-learning workloads for its binary32-like exponent
range and reduced storage and arithmetic precision. Software routines can
support processors without floating-point instructions, but the assignment's
ordered NaNs, truncation and underflow quirk must not be mistaken for a
standards-compliant replacement. A tiny finite-domain lookup can accelerate
nonlinear functions in embedded systems when its storage cost is acceptable.
